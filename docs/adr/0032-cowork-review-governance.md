# Cowork review governance

## Status

Proposed. Implementation is technical evidence, not architecture acceptance.

## Context

Multi-project orchestration needs review beyond a single pass, bounded learning,
and component-role enforcement without refactoring the TypeScript repository.
Existing ADRs 0021, 0027 and 0028 retain host control-plane and approval authority;
this decision extends engineering evidence, not that authority.

## Options considered

1. Host-owned additive TypeScript policy modules (chosen): compatible with existing
   injected execution seams, testable without external effects, keeps credentials
   and grants outside workers. Requires explicit core wiring and durable retention.
2. Worker-supplied approval/risk fields: convenient receipt integration but gives
   generated output policy authority and cannot prove independent human approval.
3. Repository-wide role migration or Rust port: stronger broad restructuring, but
   exceeds the scoped task and risks unrelated behavior and package compatibility.

## Decision

Use additive host policy modules, exact revision binding and canonical family
selection. Gate new classified components without exceptions; identity-ratchet
legacy violations outside them. Treat unclassified historical code as advisory
outside the requested scan, never as proof that the whole repository conforms.

## Consequences

The core owns audit persistence, admission, risk classification and actual provider
routing. Review success is engineering readiness only. Existing sandbox providers
may receive credentials/network access; these modules do not change or claim to
enforce sandbox isolation. Generated artifacts must be regenerated by their owner,
not manually merged. Learned proposals never autonomously change instructions.
